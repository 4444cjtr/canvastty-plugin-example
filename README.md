# canvastty-plugin-example

Example of a working plugin for plugin indexing.

---

## Модуль индексации плагинов CanvasTTY

Этот репозиторий — эталонная структура плагина для системы индексации плагинов CanvasTTY.
Ниже описано, как устроена индексация: что ищется, как валидируется, какие лимиты действуют и зачем.

### Что такое индексация плагинов

CanvasTTY находит плагины не по реестру, а **индексируя GitHub-репозитории**:

1. **Поиск репозиториев** — GitHub-поиск по имени с префиксом `canvastty-plugin-`
   (`canvastty-plugin-* in:name`). Ищутся только публичные репозитории, доступные анонимно.
2. **Чтение манифеста** — у каждого найденного репозитория читается манифест из `metadata/canvastty.plugin.json`
   (legacy-путь `canvastty.plugin.json` в корне тоже поддерживается).
3. **Валидация** — манифест проходит строгую проверку (см. «Лимиты»).
4. **Фильтрация по платформе** — репозиторий попадает в витрину только если объявлен подходящий `platforms`.
5. **Отображение** — установленные плагины исключаются из витрины; у остальных показываются
   версия, автор, описание (обрезанное), иконка и версия хоста, под которую написан плагин.

Установка происходит из того же репозитория: скачивается архив репо (`main` ветка),
манифест валидируется повторно, файлы раскладываются в `userData/plugins/<pluginId>/`.

### Структура плагина (стандарт `metadata/`)

```
canvastty-plugin-<name>/
├── metadata/
│   ├── canvastty.plugin.json   ← манифест (обязателен)
│   └── icon.png                ← иконка 128×128 (обязательна для витрины)
├── app.html                    ← entry-файлы contributions (относительные пути)
├── sample.gif                  ← любые ассеты плагина
└── README.md
```

**Зачем `metadata/`**: все метаданные (манифест, иконка) лежат в одной папке и не смешиваются
с кодом плагина. Индексатор ищет только там — код плагина можно менять без пересборки индекса.

### Манифест

```json
{
  "apiVersion": 1,
  "id": "com.example.plugin",
  "name": "example",
  "version": "1.0.0",
  "description": "example of a working plugin for plugin indexing",
  "author": "4444cjtr",
  "homepage": "https://github.com/4444cjtr/canvastty-plugin-example",
  "permissions": [],
  "platforms": ["canvastty"],
  "minHostVersion": "1.2.1",
  "contributions": [
    {
      "id": "example-gif",
      "kind": "canvas-app",
      "title": "Example",
      "description": "Shows an example GIF in the workspace.",
      "entry": "app.html",
      "defaultSize": { "width": 480, "height": 320 },
      "minSize": { "width": 320, "height": 220 }
    }
  ]
}
```

Поля:

| Поле | Обязательное | Назначение |
|---|---|---|
| `apiVersion` | да | Версия формата манифеста. Сейчас `1`. Изменения, ломающие обратную совместимость, поднимают номер. |
| `id` | да | Уникальный идентификатор (обратный домен, ≤ 80 симв.). Определяет папку установки и ключ в витрине/реестре. |
| `name` | да | Человекочитаемое имя (≤ 80 симв.). |
| `version` | да | Semver-версия плагина (`X.Y.Z`). Используется для проверки обновлений: если в репо версия выше установленной — предлагается обновление. |
| `description` | да | Описание (≤ 2000 симв.). В UI обрезается до 400 с многоточием. |
| `author` | нет | Никнейм автора (≤ 120 симв.). Показывается в карточке установленного и в витрине. |
| `homepage` | нет | Ссылка на репозиторий/сайт. |
| `permissions` | да | Массив разрешений (только из известного набора). Запрашиваются у пользователя при установке. |
| `platforms` | нет | Массив платформ, под которые написан плагин, напр. `["canvastty"]`. **Фильтр витрины**: если поле объявлено и не содержит `canvastty` — плагин не индексируется. Если плагин поддерживает несколько платформ (`["canvastty", "canvastty-superkruto"]`) — он виден. Отсутствие поля = legacy-плагин, совместим со всеми. |
| `minHostVersion` | нет | Минимальная версия CanvasTTY, под которую написан плагин (semver). В витрине/карточке показывается как `CanvasTTY:X.Y.Z`: зелёным если плагин для более новой версии хоста, оранжевым если для более старой. **Не блокирует** установку — только информирует. |
| `contributions` | да | 1–32 точки входа (см. ниже). |
| `settingsContribution` | нет | id contribution вида `canvas-app`, открываемого как экран настроек плагина. |
| `modules` | нет | Модули (необязательные пакеты кода с собственными permissions), `coreFiles` обязателен при наличии модулей. |

### Contributions (точки входа)

| kind | Назначение | Размер |
|---|---|---|
| `canvas-app` | Нода в рабочем пространстве (как у этого плагина — гифка). | `defaultSize`/`minSize`: width ≥ 320, height ≥ 220 |
| `home-widget` | Виджет на Home-экране. | `defaultSize` в колонках/рядах: 1–48 × 1–36 |
| `window` | Отдельное окно. | `defaultSize`/`minSize`: width ≥ 320, height ≥ 220 |

### Лимиты

#### Валидация манифеста

| Что | Лимит | Зачем |
|---|---|---|
| `id` | ≤ 80 симв. | Ключ в реестре, папка на диске, ссылки протокола. |
| `name` | ≤ 80 симв. | Заголовок карточки. |
| `version` | ≤ 40 симв., semver | Сравнение обновлений. |
| `description` | ≤ 2 000 симв. | Валидатор пропускает длинные описания, UI обрезает до **400** с `…` — баланс между полнотой в репо и читаемостью в интерфейсе. |
| `author` | ≤ 120 симв. | Строка «Автор: …». |
| `icon` path | ≤ 180 симв. | Путь к файлу иконки. |
| `permissions` | только известные | Безопасность: плагин не может запросить неизвестное разрешение. |
| `contributions` | 1–32 | Защита от «манифестов-простыней». |
| `settingsContribution` | ≤ 64 симв., ссылка на canvas-app | Не может указывать на виджет. |

#### Пакет (архив репозитория)

| Что | Лимит | Зачем |
|---|---|---|
| Размер архива | ≤ 25 МБ | Ограничение скачивания. |
| Число файлов | ≤ 500 | Защита от zip-бомб и мусорных файлов. |
| Размер одного ассета | ≤ 8 МБ | Отдельные файлы (гифки, медиа). |
| Манифест | ≤ 128 КБ | Метаданные не должны быть тяжёлыми. |
| Иконка | ≤ 512 КБ, 128×128 | Лёгкая загрузка иконок батчем для витрины. |
| `storage` (на плагин) | ≤ 64 КБ | Квота плагинного хранилища. |

#### Индексация и поиск

| Что | Лимит | Зачем |
|---|---|---|
| Поиск по префиксу | `canvastty-plugin-*` | Только целевые репозитории, никакого шума. |
| Результаты поиска | ≤ 10 | Быстрый ответ UI. |
| Витрина | ≤ 10 на страницу (пагинация) | Читаемость. |
| Установленные | исключаются из витрины | Не предлагать уже установленное. |
| Таймаут GitHub | 15 с | Не вешать UI на медленную сеть. |

### Оптимизация запросов (rate limits)

Индексатор бережёт GitHub API:

- **Кеш метаданных репо** (`githubMetadataCache`) — владелец/ветка кешируются на сессию.
- **Батчинг GraphQL** — манифесты и иконки запрашиваются пачками (до 8 репо на запрос)
  одним запросом к `api.github.com/graphql`, а не по одному.
- **Fallback без токена** — при отсутствии токена файлы читаются с `raw.githubusercontent.com`.
- **Иконки батчем** — `plugins:icon` принимает массив URL и возвращает `Record<url, dataUrl|null>`,
  UI не дёргает по одному запросу на иконку.

### Версия софта в манифесте

`minHostVersion` — это **данные, а не ограничение**:

- Витрина и карточки показывают `CanvasTTY:X.Y.Z` под автором.
- Зелёный цвет — плагин написан под более новую версию хоста, чем установлена (ознакомиться,
  обновить хост при желании).
- Оранжевый — плагин написан под более старую версию.
- Установка/обновление **не блокируются** несовпадением версий.
